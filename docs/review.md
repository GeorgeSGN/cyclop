# Отчёт для ревьюера

Форк [akalikbergenov/cyclop](https://github.com/akalikbergenov/cyclop) (MIT) под личное
использование. Дата: 2026-08-06. Ветка: `main`, upstream — `upstream/main`.

Приложение — панель, живущая в чёлке MacBook: раскрывается по наведению курсора,
складывается когда курсор уходит. Нативный SwiftUI + AppKit, ноль внешних
зависимостей, сборка через SwiftPM без Xcode-проекта.

## Как ревьюить

```bash
git clone git@gitlab.com:george_ns/cyclop.git && cd cyclop
git remote add upstream https://github.com/akalikbergenov/cyclop.git && git fetch upstream

git diff upstream/main..HEAD          # весь дифф от оригинала
git log --oneline upstream/main..HEAD # 5 коммитов

./Scripts/bundle.sh release && open build/Cyclop.app
```

Требуется macOS 15+ и Swift 6. Сборка занимает секунды, тестов в проекте нет —
ни в оригинале, ни здесь.

## 1. Урезание набора вкладок

Оставлены полка, буфер, заготовки, перевод. Удалены плеер, календарь, заметки.

Удалённые файлы: `MediaController`, `NowPlayingFeed`, `PlayerBridge`,
`CalendarStore`, `NoteStore`, `MediaPane`, `CalendarPane`, `NotesPane`,
`Skeleton.swift`, `Sources/CyclopMediaHelper/helper.m`, а также `.github/workflows`
(GitHub Actions на GitLab не работает, бесплатных macOS-раннеров нет) и
`Scripts/release.sh` (делал релиз через `gh` в репозиторий автора).

**На что смотреть.** Вместе с плеером ушли две вещи, которые стоили дорого:

- **приватный `MediaRemote.framework`.** Оригинал добирался до него через dylib,
  загруженный в `/usr/bin/perl` — единственный процесс, которому демон
  `mediaremoted` доверяет начиная с macOS 15.4. Решение изобретательное, но
  висит на том, что Apple не уберёт perl из системы и не закроет этот маршрут;
- **разрешение на Календарь** — единственное TCC-разрешение оригинала.

Побочный результат: `0` разрешений, `1.7 MB` бандла вместо `2.1 MB`, в бандле
только бинарь, иконка и две `.lproj`.

Изменения в общих файлах — механические: убраны кейсы из `enum Tab`, из двух
свитчей `NotchContentView`, вызовы `setActive` в `NotchController`, компиляция
хелпера и три usage-description из `Scripts/bundle.sh`, мёртвые ключи из таблиц
локализации. Правый рейл иконок удалён — он существовал только потому, что
семь иконок не влезали в высоту панели.

## 2. Копирование с полки

**Проблема.** Выделенную карточку нельзя было скопировать с клавиатуры: ⌘C на
полке не доходит до приложения вообще. Панель забирает клавиатуру только на
вкладках с текстовым полем, на полке она никогда не key-окно.

**Решение.** Не ⌘C, а копирование в момент выбора: `ShelfStore.select()` в
дополнение к выделению кладёт выборку в буфер.

**Почему не ⌘C.** Чтобы он работал, панель обязана стать key-окном, а это тускнит
заголовок и гасит каретку в окне под панелью — ровно та цена, из-за которой автор
включил клавиатуру только на вкладках с полем. Клик закрывает задачу без неё.

**Что проверено по коду, а не предположено:**

- `ShelfDragSource.mouseUp` вызывает `onClick` только если драга не было —
  перетаскивание карточки буфер не перезаписывает;
- `ClipboardStore.poll()` выходит на маркере `com.cyclop.internal` — копии с
  полки не засоряют историю буфера.

Снятие выделения буфер не трогает: положить карточку не должно означать «забрать
обратно то, что скопировано».

## 3. Мультивыбор: пути вместо картинки

Здесь была ошибка в первой версии, поэтому подробно.

Сначала при мультивыборе в каждый элемент буфера кладлась и ссылка на файл, и
сама картинка. Замер показал, что буфер формируется правильно (3 элемента,
`public.file-url` + `public.png` в каждом), но Claude Code в терминале вставлял
одну картинку.

**Причина.** Claude Code читает буфер через
`osascript -e 'the clipboard as «class PNGf»'` — один запрос, одно значение.
Найдя картинку, он до текста не доходит. То есть картинка в буфере **блокирует**
альтернативный путь, а не дополняет его.

**Итог.** Байты картинки кладутся только когда скопирована одна карточка. При
нескольких — ссылки на файлы плюс список путей текстом:

| | одна карточка | несколько |
|---|---|---|
| Finder, мессенджеры | файл ✓ | все файлы ✓ |
| редактор, чат картинкой | картинка ✓ | ничего |
| терминал, читающий путь | картинка ✓ | все файлы ✓ |

Проверено на живом буфере: `PNG нет`, 3 × `file-url`, текст с 3 путями; Claude
Code разобрал список и подтянул все три файла.

Побочно исправлен баг оригинала: JPEG отдавался под типом `.tiff` — байты JPEG с
заголовком «это TIFF», такую картинку не декодирует никто. Теперь PNG идёт как
есть, остальное переупаковывается в настоящий TIFF.

Предохранитель: `imageDataBudget = 64 MB`. ⌘-клик по шестидесяти карточкам — один
жест, а выборка читается в память целиком.

## 4. Автоудаление скриншотов

`ScreenshotVault.prune()` удаляет снимки старше 14 дней **безвозвратно**, не в
Корзину. Запуск при старте и раз в сутки (`AppDelegate.startSweep`) — дневной
такт нужен маку, который не перезагружается месяцами.

**Расхождение с оригиналом намеренное.** У автора папка не чистится никогда, это
заявленный принцип: «папка принадлежит пользователю». Здесь снимок из буфера
считается одноразовым, а Корзина, медленно заполняющаяся такими, — та же проблема
на папку дальше.

Карточки на полке не исключение: две недели значит две недели, иначе полка
становится тем самым вечным хранилищем. После уборки вызывается `reloadShelf()`,
и карточки с исчезнувшими файлами уходят. Файлы, затащенные на полку из других
мест, не трогаются — подметается только `~/Pictures/Cyclop/`.

Ручная кнопка «Очистить папку» по-прежнему кладёт в Корзину: осознанное нажатие
заслуживает обратимости, автоуборка — нет, её никто не звал в момент запуска.

Проверено: копия снимка с датой 17 июля удалена при старте, все 10 сегодняшних
целы.

## 5. Вкладка «Утилиты»: блокировка клавиатуры

Пятая иконка в рейле, внутри — одна кнопка во всю плашку. Не список из одного
элемента: раскладку под то, чего ещё нет, пришлось бы угадывать сейчас и
переделывать потом.

**Механизм.** `CGEventTap` в режиме `.defaultTap` на `.cghidEventTap`, маска
`~CGEventMask(0)` — все типы событий, а не список. Колбэк возвращает `nil`, что
и есть отбрасывание события.

**Требует Accessibility.** Это первое TCC-разрешение приложения, и его не
обойти: единственная альтернатива — перетянуть фокус на своё окно, и тогда ⌘Q,
⌘Tab, Caps Lock и клавиши яркости всё равно проходят. Приложение, которое
выглядит заблокированным, но не заблокировано, хуже отсутствия фичи: тряпке
доверяют под обещание, которое не выполняется.

Разрешение спрашивается не сразу: первое нажатие показывает объяснение в панели и
поднимает системный диалог, второе (если разрешения всё ещё нет) открывает нужный
раздел настроек. Диалог, выпрыгнувший до объяснения, неотличим от программы,
которая сама полезла к вводу.

**Три выхода из режима, независимые друг от друга:**

1. удержание **Esc** или **`-`** три секунды — клавиши матчатся по key code, а не
   по символу: на кириллице сравнение по символу молча не сработает, автор уже
   поймал это на ⌘C. Автоповтор keyDown не сбрасывает отсчёт, любая другая
   клавиша — сбрасывает;
2. **автоснятие через 60 секунд**, неотключаемое;
3. macOS сама выключает tap, если колбэк перестал отвечать (`tapDisabledByTimeout`).
   Обработано с повторным включением — разница между блокировкой, которая
   восстановилась, и той, которая молча перестала блокировать.

Плюс четвёртое, вне кода: tap умирает вместе с процессом, так что kill снимает
блокировку.

**Оверлей** (`CleaningOverlay`) — чёрное окно на каждом дисплее, уровень
`CGShieldingWindowLevel()`. Две причины: заблокированный мак, выглядящий обычно,
неотличим от зависшего, а на чёрном фоне видны разводы, так что экран протирается
в том же проходе. Подсказка и прогресс удержания показываются на дисплее под
курсором. Подписка на `didChangeScreenParameters` — подключённый в процессе
монитор иначе остался бы неприкрытым.

Первая версия накрывала внешний монитор частично, прямоугольником не по месту.
Причина — `NSWindow(contentRect:…screen:)` читает rect относительно левого
нижнего угла переданного экрана, а `screen.frame` уже глобальный, так что origin
складывался сам с собой. Замер на двух дисплеях:

```
внешний: screen.frame = (1728, -323, 2560, 1440)
было  → окно в (3456, -646)   ← 1728+1728, -323+-323
стало → окно в (1728, -323)   ← setFrame, координаты глобальные
```

Окна теперь создаются с нулевым rect и позиционируются `setFrame`, которому
перевод координат не нужен.

Панель при блокировке закрывается, поллинг курсора останавливается: пока события
гасятся, отслеживать нечего.

## Риски и ограничения

**Ad-hoc подпись и Accessibility.** macOS привязывает выданное разрешение к
подписи. Мы подписываем ad-hoc, поэтому **после каждой пересборки разрешение
придётся выдавать заново**. Лечится постоянным самоподписанным сертификатом —
не сделано, отдельная задача.

**Нет тестов.** Их нет и в оригинале. Проверялось запуском и замерами:
структура буфера читалась отдельным скриптом, уборка — на подставном файле со
старой датой.

**Конфликты при обновлении из upstream** ожидаются в `NotchViewModel.swift`,
`NotchContentView.swift`, `ShelfStore.swift`, `ScreenshotVault.swift`,
`AppDelegate.swift`, `Scripts/bundle.sh`.

**Блокировка проверена частично.** Геометрия оверлея — замером на двух дисплеях
(см. выше). Поведение под активным tap — удержание клавиш, автоснятие,
`⌘Tab` — требует выданного разрешения и живого нажатия; на момент отчёта не
проверено.

## На что смотреть в первую очередь

1. `KeyboardLock.handle` — колбэк tap. Гасит всё, работает на главном потоке,
   ошибка здесь означает мак, у которого не работает ввод.
2. `KeyboardLock.unlock` — снятие tap и порядок разрушения. Утечка `CFMachPort`
   или неснятый run loop source оставят блокировку жить.
3. `ShelfStore.copy(_ urls:)` — почему картинка кладётся только для одиночного
   файла; логика неочевидна без контекста из пункта 3.
4. `ScreenshotVault.prune` — необратимое удаление файлов пользователя.
